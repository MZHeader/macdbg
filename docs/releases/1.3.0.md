# macdbg 1.3.0

**Sandbox exec & scripts** now gates exported in-process OSA execution APIs as
well as process launches. Interactive mode prompts before script execution;
automatic mode returns cancellation. Allow executes the real call, Block returns
`userCanceledErr`, and Fake success produces an empty result. OSA dumps save
captured script bytes without evaluating script-engine helpers. Gates also intercept
instruction stepping and bind decisions to their original stopped thread.
See the [exec sandbox guide](../../.skills/macdbg-agent/references/exec-sandbox.md)
for the seven covered APIs and the containment boundaries.

Payload capture observes descriptor creation/replacement and successful OSA
load/compile operations. It tracks descriptor aliases and component-scoped script
IDs, retaining input bytes after descriptor disposal. Dump saves compiled `.scpt`
data or original source bytes and leaves execution paused. Missing capture is
reported explicitly; metadata is never substituted for a payload. Inputs and
caches are bounded, and opaque file-only or unobserved loads can remain unavailable.
GUI decisions carry a stop token, preventing stale buttons from acting on a later
call. Restart clears pending GUI decisions and transparently handles capture
observers encountered before the entry point.

OSA prompts display source or a static AppleScript reconstruction before capture
metadata. **Dump content + raw** saves readable UTF-8 text alongside compiled
bytes, with both paths retained on reconnect. A bundled, bounded Python worker
supports run-only reconstruction without executing scripts or downloading tools.
Reconstructed names and control flow may be incomplete; the original captured
bytes remain authoritative. Parser failures leave the raw dump available and
report why readable content could not be recovered.
The content-preview update passed 36 focused host checks and 16 guest checks,
including both complete script and standalone handler storage, run-only input,
Unicode source, malformed input, parser timeout, exact raw dumps and GUI replay.

**Hide debugger pauses** adds automatic clock compensation on native ARM64.
Enable it at the initial entry stop from the Defenses dialog or with
`defense_enable {"name":"auto_clock"}`. It needs no timing-check addresses,
register assignments, thresholds, or decoded target symbols. Observed debugger
pauses are subtracted; normal execution and intentional sleeps still advance time.

The mode discovers main-executable Mach-O imports for Mach clocks,
`clock_gettime`, `gettimeofday`, and `mach_wait_until`. It also handles supported
OS clocks resolved through the executable's `dlsym` import. A process-local
page contains frameless forwarders, written as data and then protected
read/execute. Breakpoints live on those forwarders, leaving system clocks and
main `__TEXT,__text` unchanged. Framework imports retain their native behavior.

A bounded scan finds main-text `CNTVCT_EL0` and `CNTPCT_EL0` reads and arms
hardware breakpoints. A small native counter reader runs only in the debugger.
`clock_status` reports covered APIs, forwarder entry points, import bindings,
dynamic resolutions, hits, pause time, errors, and partial counter coverage.
Modified hooks, forwarders, import slots, or counter instructions block resume.
Failed setup rolls back import writes; failed restoration keeps execution blocked.
Disabling restores owned imports and retains forwarders until process exit so
previously cached function pointers remain callable.

Concurrent main-thread and worker-thread clock reads share pause accounting.
Threads stopped incidentally at a clock entry are handled without consuming an
unrelated user stop. GUI and headless execution use the same compensation,
including instruction stepping. Duplicate headless stop notifications no longer
resume the target twice.

Cloak improvements:

- `sysctlbyname("kern.hostuuid", ...)` uses the same UUID as the IOKit property
  cloak. Length probes report 37 bytes including NUL. Unsupported kernel keys
  keep their native errors; this does not manufacture support for absent keys.
- Failed sysctl reads inspect the current thread's `errno` through debugserver
  thread metadata and memory reads. No return-time `__error` call is injected.
  Worker threads and restarts use fresh metadata; unreadable state fails closed.
- Temporary cloak and debugger-flag return hooks are retired during dispatch,
  preserving hardware stop IDs on older LLDB versions and retaining thread
  ownership until consumption.
- A duplicate exception immediately after hardware return-hook retirement is
  retried once when process, thread, consecutive stop IDs, PC, and instruction
  bytes match. The retry is logged, skips no instruction, and rejects live
  breakpoints or concurrent real stops. Unmatched exceptions remain visible.
  Darwin's interrupted-continue single-step exception receives the same bounded
  treatment when hardware sites are armed and the pre-resume thread position
  and instruction are unchanged. User stepping is excluded.
- Deferred IOKit hooks tolerate unresolved retained locations after restart
  while the framework is unloaded. Disabled or unexpectedly unresolved hooks
  still block execution.
- Self-trap forwarding is restricted to target `brk #0` instructions with a
  registered handler. System runtime assertions, other BRK immediates, and
  unhandled traps are surfaced normally.

Advanced **Timing rules** provide hardware-backed register replacement, masked
register updates, and redirection at verified ARM64 timing decisions. Rules save
per binary with module-relative offsets and expected instruction bytes. They
rearm on same-target restart and load disabled in a new session. Stale instructions,
missing hooks, and exhausted hardware slots produce explicit errors.

Automatic clocks and manual timing rules are mutually exclusive, start disabled,
and are not implicitly enabled by Analysis cloak or Enable ALL. Use Analysis
cloak alongside either mode for broader anti-analysis and text-integrity protection.
`MACDBG_STATE_DIR` optionally isolates saved state and agent records for testing.

## Coverage boundaries

Automatic compensation is approximate. Import pointers and the forwarder page
are observable. Pointers cached before activation, unsupported import layouts,
other resolution APIs, calls from other modules or generated code, external
clocks, and other counter instructions are outside coverage. Unsupported clock
IDs and invalid API arguments pass through. Main-caller `mach_wait_until`
deadlines are translated at entry; later debugger pauses during the kernel wait
and other absolute-deadline APIs are not virtualized. Transport and scheduling
overhead remains measurable. Inspect counter coverage separately from hook safety.

Numeric-MIB UUID queries and `gethostuuid()` are outside the UUID addition.
IOKit string handling and self-trap handler lookup still use target-side helper
expressions; the errno change does not eliminate every target-side expression.
Intermittent Objective-C / LaunchServices lock assertions have been observed
during framework initialization on macOS 15 with the cloak enabled. The root
cause remains unresolved. These assertions remain visible as real debugger
stops; they are never automatically skipped. Restarting can recover, but is not
a guaranteed fix.

## Validation

Validation uses source-built benign fixtures for delayed timing decisions,
dynamic clock resolution, intentional sleeps, waits, errors, concurrent reads,
optimized and stripped builds, framework loading, thread ownership, restart,
stepping, shared user stops, trap handling, and failure rollback.

The [automatic clock guide](../../.skills/macdbg-agent/references/automatic-clocks.md),
[timing rule guide](../../.skills/macdbg-agent/references/timing-rules.md), and
[README](../../README.md) contain controls and validation commands.

Release checks passed on native ARM64 macOS 26.6.2 with LLDB 2100.0.17.203:
157 unit tests and 110 native integration checks, with focused reruns after
final GUI and test-fixture updates. OSA coverage includes all seven
execution APIs, Allow/Block/Fake, output guards, deferred framework loading,
restart, stepping, and GUI decisions. GUI reconnect/prompt checks were repeated
after the final UI update. Benign guest checks also passed on
macOS 15.6.1 with LLDB 1700.0.9.502, including repeated hardware return stops and
worker-thread errno across thread exit and restart. All eleven OSA integration
tests also passed in that guest, including exact source/compiled dumps, shared
descriptor ownership, disposal, restart and unavailable-capture handling.
The script / identity-query / application-registration sequence also passed
three independent launches on each OS. This does not establish that the
intermittent framework assertion described above is fixed.

Python compilation, JavaScript syntax, skill validation, and the rebuilt 1.3.0
app bundle's signature checks passed. The bundle remains a launcher for this
checkout and requires the documented local Python/LLDB and GUI dependencies;
it is ad-hoc signed, not notarized.
